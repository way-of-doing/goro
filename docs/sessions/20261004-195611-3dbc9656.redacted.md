Is there an obstacle to adding `file::size` as a definite number identifier?

## Claude

No, there's no real obstacle. My earlier note was only that `identifiers.md` never states it. The docs already guarantee that `file::size` is exactly one value whenever a predicate is evaluated.

**Why it's always exactly one:** `concepts/warnings.md` puts every case where the size can't be had in the file-warning category. If a file has gone since it was discovered, or permission is refused, the run warns and doesn't process that file. The predicate is never evaluated for it, so `file::size` never has to be absent or unusable. Whenever it does resolve, it's one value from the file system.

**One thing to check in the wording:** `file::size` is a bytecount, not a number. Definiteness doesn't depend on type, so it can be a definite bytecount. Turning it into a number would lose `file::size > 1kb` and the rule that a bare literal like `1000` means bytes.

**What the change would involve (edits, not obstacles):**
- `predicates.md`: "An identifier is never definite, whatever its namespace" becomes "definite only where its documentation says so". The "Definite expressions" list gains an entry for those identifiers.
- `evaluation.md`: the identifier row in the static judgements table changes from "no" to "as declared".
- `identifiers.md`: one sentence in the `file` section saying which identifiers always resolve to exactly one occurrence, and are therefore definite.
- `rationale.md`: the multivalues section already says definiteness is a property of the predicate's text, not of a value, so declaring it per identifier, the way type is declared, fits without new argument.
- The real cost is that it's a promise: making one of these identifiers non-definite later would break predicates like `file::size != 0`.

**`file::duration` probably qualifies on the same grounds.** `warnings.md` says a file whose audio properties can't be parsed is unreadable, so it never reaches evaluation either. But the docs don't say whether a readable file can lack a duration, so that would need deciding before including it.
